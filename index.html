Announcing rustup 1.29.1

The rustup team released version 1.29.1, introducing several improvements to the recommended tool for installing Rust. The release includes better concurrency in certain rustup operations, and implicit installation of the active toolchain in rustup-init and rustup invocations has been deprecated, now producing a warning instead. New features include a `--serve` flag for `rustup doc` that serves documentation over local HTTP, and rustup now officially supports aarch64-pc-windows-gnullvm as a host platform. Installing i686-pc-windows-* toolchains on 64-bit Windows now requires the `--force-non-host` flag, and `rustup-init` no longer leaves unexpected files behind after cancelled installations. The terminology "target triple" has been renamed to "target tuple" throughout the project, and a bug causing Windows installation failures with rustup-init.sh has been fixed. Users can update by closing programs that use rustup and running the standard update command.

Some more things about Django I've been enjoying

The author is learning to build traditional backend-rendered websites using Django, having previously relied on static site generators and frontend-heavy approaches. They particularly enjoy Django's query builder pattern using queryset classes with named methods for filtering, template filters like urlize, json_script, and querystring, and the automatic database migration system. However, they dislike using class-based inheritance to share code between views and switched to function-based views instead. While exploring performance, they discovered they had accidentally disabled the cached template loader, and re-enabling it dramatically improved their site's capacity from roughly 2-3 requests per second to about 12. They find Django's performance characteristics more complex than Go's but have found CPU profiling more immediately useful than the common advice to simply add database indexes.

Learning a few things about running SQLite

The author shares lessons learned while running SQLite for a Django site. Turning on WAL mode was the initial step, but running ANALYZE dramatically improved query performance, reducing a 5-second FTS5 query on 4000 rows to about 0.05 seconds by generating statistics for the query planner. Cleaning up the database proved tricky because long-running DELETE statements exceed the 5-second write timeout, causing other workers to crash and the VM to shut down; the workaround is performing cleanup in small batches. Backups are handled two ways: using restic with VACUUM INTO commands, and Litestream for incremental backups. The author also notes that SQLite databases can be split across multiple files, which worked well for the Mess with DNS project that has run on SQLite since 2022.

Moving away from Tailwind, and learning to structure my CSS

The author migrated several websites away from Tailwind toward semantic HTML and vanilla CSS after eight years of using the framework. They organized their CSS into distinct sections including a reset copied from Tailwind's preflight styles, component-based stylesheets where each component has its own class and file, CSS variables for colors and font sizes, utility classes, base styles, and spacing rules. For responsive design, they moved away from media queries toward flexible CSS grid layouts using features like auto-fit and grid-template-areas. In development they rely on built-in CSS @import statements and nested selectors, bundling with esbuild only for production. The author cited several reasons for migrating, including Tailwind's growing reliance on a build system, their improved CSS skills, the framework's limitations when attempting unconventional styling, and curiosity about writing more semantic HTML.

crates.io: development update

Over the past six months, crates.io introduced a new "Code" tab that lets users browse the contents of published crate versions directly on the site, powered by zip archives stored on a CDN. The team also accepted RFC #3946, beginning the implementation of crates.io-native usernames independent of GitHub as a precursor to supporting other identity providers. Additional user-facing changes include warning banners for unmaintained crates flagged by RustSec, "You might not need this dependency" notices for crates superseded by the Rust standard library, and an animated Ferris on error pages whose eyes follow the cursor. The frontend was successfully migrated from Ember.js to Svelte, reaching feature parity and becoming the default in May. Under the hood, improvements ranged from faster search and reverse-dependency lookups to a rewritten ARCHITECTURE.md document, better CDN caching, accessibility enhancements, and optimizations to the background git index worker.

Griotte: Verified Compartmentalisation via Capabilities

CHERIoT is a hardware-software co-design that uses hardware capabilities to define compartments within the CHERIoT RTOS, isolating them by default to limit damage from bugs or malicious behavior. Cross-compartment communication is mediated by a privileged component called the switcher, which enforces isolation between compartments and guarantees stack safety. The authors introduce Griotte and Griotte OS, idealized but faithful versions of the CHERIoT machine and RTOS, to address two questions: formalizing the informal notion of compartmentalisation and verifying that CHERIoT enforces its intended security guarantees. They capture these guarantees using a continuation-based logical relation that models the combined behavior of the switcher and the capability machine, and they define a specification for the switcher that they prove the implementation meets. The verification is modular, verifying compartments individually before composing their specifications, and the approach is demonstrated on scenarios including local state integrity when sharing memory with unknown code.

A Dynamic Intermediate Representation for Hybrid Quantum-Classical Programs

A new Intermediate Representation (IR) is proposed for hybrid quantum-classical programs, addressing the limitations of traditional quantum compilers that rely on the static circuit model. The paper notes that this static view breaks down when gate choices depend on runtime data or measurement results, a common situation in hybrid applications. The new IR elevates gates to first-class values, enabling their dynamic creation, composition, and control so that classical computation can steer quantum behaviour. This unified framework captures phenomena including stochastic gate selection, adaptive error correction, and measurement-driven computation. Case studies in noise modelling, randomised compilation, error correction, and measurement-based quantum computing demonstrate that the IR expresses these programs compactly and enables optimisations previously impossible under the circuit model. Evaluation on a benchmark suite of hybrid quantum-classical programs confirms that the IR supports both compact representation and effective compiler analysis and transformation.

Predicting Program Exit Code with LLMs and Programming Language Semantics

The paper introduces Program Executability Prediction (PrEx), a task that asks models to determine whether a program is semantically valid or invalid and, if invalid, which formal rule it violates given the program's syntax and operational semantics. The authors investigate whether LLMs rely on pre-training priors or systematically apply the provided semantic rules. To support this task, they constructed a dataset containing systematically generated invalid transformations derived from valid programs. They evaluated open-source coding LLMs under two semantic formalisms and two semantic shifts across Human-Written, LLM-Translated, and Fuzzer-Generated program splits. Their findings show that LLMs lean on pre-training priors rather than applying the given rules, performing especially poorly on modified semantics. Performance further degrades as program complexity increases.

Beyond Locks and Thread IDs: Static Data Race Detection Off The Beaten Path (Extended Version)

The paper "Beyond Locks and Thread IDs: Static Data Race Detection Off The Beaten Path" by Daniel Bund, Julian Erhard, Michael Petter, and Michael Schwarz extends the digest framework for static data race detection by incorporating abstractions of thread execution history to improve precision. The authors add support for concurrency constructs previously overlooked in static race analysis, including thread barriers and pthread_once, which ensures an action executes only once. They also instantiate the framework with an abstraction of locksets held by ancestor threads. To evaluate these extensions, the authors propose a suite of litmus tests and compare their implementation against state-of-the-art tools, finding that existing analyses lack support for these synchronization features. The extended version spans 49 pages and includes 12 figures and 6 tables.

SUN: Persistent Programs For Language-Grounded Control-to-Learning-to-Real Policies

The paper introduces Semantically UNified (SUN) Programs, typed executables where geometric and contact relations are defined once and compiled into aligned Model Predictive Control costs, satisfaction predicates, reinforcement learning rewards, transition guards, and diagnostics. The system, Kuafu, driven by large vision-language systems, automatically synthesizes SUN Programs from language and scene semantics, screens feasibility via MPC, and retains semantics while training stage-conditioned policies. Across nine tasks, Kuafu achieves 82.03% macro-success, outperforming sparse-reward (35.67%) and Stage-BC (24.75%) baselines. At 8192-way scale, it generates 10.57 times the successful trajectory time per hour of human teleoperation. With 500 trajectories per task, Kuafu data trains DP3 policies to 46.0% simulation success compared to 22.4% for alternatives, and achieves 34.7% success on physical Franka and Kinova robots. The results demonstrate that simulation-screened task semantics can amortize control into robust policies without demonstrations or manual dense rewards.

AnkiDroid: Google Play no longer allowing Open Collective donation link

AnkiDroid, a free open-source flashcard app with over 10 million Android installs, is facing removal from Google Play on September 11 in all countries except India and Russia after Google rejected its updates since August 28. The dispute centers on AnkiDroid's donation link to Open Source Collective, its US-based fiscal host that holds 501(c)(6) tax-exempt status. Google Play's payments policy prohibits apps from directing users to external payment methods unless collecting donations for a "validated tax-exempt organization," and Google has refused to accept AnkiDroid's IRS determination letter as proof of tax exemption. Despite 501(c)(6) being a recognized tax-exempt classification under which donations are not tax-deductible for donors, Google has not explained why this status is insufficient. AnkiDroid is removing its donation links from the next Play Store build (2.24.X) under protest to preserve distribution, while seeking clarification from Google.

AI Coding Agent Skills for Real Engineers

Matt Pocock created a set of AI coding agent skills designed for real engineering rather than vibe coding, built on decades of software development experience. The skills are small, composable, and work with any model, addressing four common failure modes: misalignment between user and agent, excessive verbosity, code that doesn't work due to weak feedback loops, and the rapid accumulation of codebase complexity. Users can install them either as a managed Claude Code plugin that auto-updates or as editable files via skills.sh for full customization. After installation, running /setup-matt-pocock-skills once per repo configures the issue tracker, triage labels, and documentation layout. Key skills include /grill-me and /grill-with-docs for aligning with the agent, /tdd and /diagnosing-bugs for feedback-driven development, and /improve-codebase-architecture for regular design reviews, split into user-invoked orchestrators and model-invoked disciplines.

RotaryCell: Making an unmodified rotary phone work over LTE with an ESP32-S3

RotaryCell is a project that converts an unmodified rotary telephone into a battery-powered, portable cellular telephone while preserving the original handset, rotary dial, switch-hook, mechanical ringer, and network block without drilling or permanently altering parts. A hand-wired prototype has been validated and operates, while two newly ordered PCBs—an Audio and Reset board and an AG1171 through-hole carrier board—are awaiting assembly and testing as of August 28, 2026. The system uses a LilyGO T-A7670G-S3 board combining an ESP32-S3 controller and A7670 cellular modem, a Silvertel AG1171 subscriber-line interface for line circuitry and ringing, and a protected 21700 battery cell. Supported functions include rotary pulse dialing, incoming and outgoing cellular calls, physical bell ringing, North American tones, adjustable bidirectional audio, battery monitoring, AT-command diagnostics, and OTA updates, with service codes for maintenance Wi-Fi and modem diagnostics. The repository serves as a public engineering archive documenting the prototype, currently running firmware v0.10.4, and is licensed under MIT, with files representing the exact boards ordered rather than production-tested hardware.

Fine, I’ll build my own text editor

The author was inspired to build a custom text editor after struggling with VS Code's Monaco Editor. Their first experiment rendered everything on a `<canvas>` element at 60–120fps, implementing basic features like pointer-based cursor positioning, arrow key navigation, line highlighting, and typing. However, this approach lacked text selection, undo/redo history, multi-line paste, overflow scrolling, and accessibility support. Switching to a `contenteditable="plaintext-only"` div provided native accessibility, selection, and undo features for free, but issues emerged with larger character counts in Chromium browsers. A final version using a `<textarea>` proved more performant for longer text and enabled syntax highlighting via CSS. The author concludes that while the project demonstrates a promising foundation, challenges remain around tab indentation, virtualised scrolling, and handling UTF-16 code units.
