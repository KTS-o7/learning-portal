Go 1.27 is released

Go 1.27 was released on August 19, 2026, bringing updates across the language, toolchain, runtime, and standard library. The language now supports generic methods, permits any valid field selector as a key in struct literals including nested or embedded struct fields, and applies function type inference in all assignment contexts such as composite literals, type conversions, and channel sends. Tool improvements include four new go fix modernizers (atomictypes, embedlit, slicesbackward, and unsafefuncs), version queries in go doc, and automatic consolidation of require blocks by go mod tidy. Size-specialized memory allocation reduces small object allocation costs by up to 30%, yielding about a 1% overall performance gain, while the goroutine leak profile in runtime/pprof is now generally available. Type Construction and Cycle Detection

Go's type checker constructs internal type representations while traversing the abstract syntax tree, populating structures like Defined, Slice, Pointer, and Array. A type is considered complete when all its fields are populated and the types it points to are also complete, which ensures that deconstruction is sound. Recursive types complicate this process because evaluation can return incomplete types, though type construction itself merely refers to types rather than deconstructing them, so it isn't blocked by incompleteness. However, problems arise when values of incomplete types appear in contexts requiring deconstruction, such as array size calculations using unsafe.Sizeof. For example, type T [unsafe.Sizeof(T{})]int creates a deadlock because sizing the array requires deconstructing T, but T cannot complete until the array does. Cycle detection identifies these impossible cases, though operations on incomplete pointer values like new(T) remain sound since pointers have uniform size regardless of what they point to.

//go:fix inline and the source-level inliner

Go 1.26 introduces a new source-level inliner as part of the redesigned `go fix` command, which replaces function calls by copying the called function's body and substituting arguments for parameters. The inliner, already used by gopls for refactorings, is now an analyzer in `go fix` and works through a new `//go:fix inline` directive that lets package authors enable self-service API migrations. Examples include renaming `ioutil.ReadFile` to `os.ReadFile` and fixing design flaws such as reversed parameter order in a hypothetical `oldmath` package. The inliner also handles type aliases and constants, rewriting references to old names to point to new ones. At roughly 7,000 lines of compiler-like logic, the tool carefully manages correctness across corner cases like parameter elimination and side effects. Google's internal use has already produced more than 18,000 changelists migrating deprecated APIs.

Supply chain attack on arrayref

On August 20, 2026, the Rust Security Response Team received a report identifying the proc-macro1 crate as malicious, containing code that downloaded a harmful payload through its build script. The team confirmed the report and removed several malicious crates from crates.io, including proc-macro1, proc-macro-en, aovine, arone, aronenao, and tinymember. They also discovered that the popular arrayref crate had been republished to depend on the malicious crate, with its recent versions yanked; the malicious version was deleted and previously yanked versions were unyanked. Additional crates by the same author, internment and append-only-vec, were likewise affected, and the author's account was locked as a precaution. While the author of arrayref is not believed to be acting maliciously, their computer or credentials were likely compromised. The team credited Nextron Systems GmbH's research team for initially discovering the attack.

Enabling the next iteration of the borrow checker on nightly

Rust is enabling Polonius Alpha, the next iteration of its borrow checker, on nightly in preparation for stabilization later this year. The original AST borrow checker was phased out in 2019 in favor of NLL, and Polonius spun out of that effort in 2018, though performance issues initially prevented adoption. A new formulation imagined in 2023 required minimal rearchitecture and could be extended to accept more code. The key improvement is flow-sensitive borrow checking of lifetime outlives relationships, allowing code that NLL incorrectly rejects to compile. Performance testing on the top 10,000 crates shows relatively few significant regressions, with worst cases at 2-3x slower. While some programs that compiled under the original Polonius won't compile with this Alpha version, the team is aiming to stabilize before the end of the year and doesn't have concrete plans for further feature work afterward.

Primal Acceleration of Newton's Method

The paper by Nikita Doikov introduces a new direct accelerated Newton method for minimizing convex functions with Lipschitz continuous Hessian, operating exclusively on primal variables with just one linear solve per iteration. Using a simple predetermined parameter choice, the algorithm achieves a global convergence rate of O(1/k³) in terms of functional residual. This is presented as the first second-order method for this problem class to attain such a rate while relying solely on one linear system solve per iteration, without requiring auxiliary nonlinear regularized subproblems like cubic regularization, nonlinear parameter searches, or dual extragradient corrections. The method can also be implemented in a Hessian-free manner using an inexact linear system solver while preserving its fast global convergence. Finally, the construction is extended to arbitrary geometry through Bregman divergence and to composite optimization problems.

VIALS: A Benchmark for Visual Interpretation of Artifacts in the Life Sciences

VIALS is a visual question-answering benchmark introduced to evaluate AI systems on interpreting scientific artifacts commonly encountered in life sciences workflows. The benchmark contains 161 interpretation tasks covering diverse artifact types, including gel blots, microscopy images, plasmid maps, flow cytometry plots, and molecular structures. Unlike benchmarks that rely on polished figures from publications and textbooks, VIALS draws from artifacts examined throughout experimental workflows in the biotech industry. While frontier vision-language models can fluently describe natural images, they struggle to accurately interpret these scientific artifacts, reflecting gaps in domain knowledge and domain-specific visual reasoning capabilities. In contrast, scientists with relevant domain expertise find these visual interpretation tasks straightforward. The authors argue that AI lacking such capabilities will have limited utility in professional life sciences workflows, where these artifacts are central to how scientists reason, communicate, and make research decisions.

AI with Authority, from Application to Silicon

The paper reports a five-week effort in which one researcher used consumer AI subscriptions to direct a small fleet of agents from application code through a verified compiler and executive to a RISC-V processor taped out on a community silicon shuttle. It says no proof passed through human review, no RTL was written by a human, and no incorrect proofs reached the record. The proposed “Salt method” makes the proof kernel the incorruptible referee: agents exchange mathematical claims as kernel-checked artifacts, while humans focus on statements, designs, and rulings. The verification chain extends from the Lean 4 kernel to SAT-checked equivalence at the silicon boundary. The author also publishes a complete accounting of the mathematics campaign, including theorem provenance, a preregistered token meter, floor-bounded human time, and an append-only error ledger with catch numbers through #256, while noting that #79 was never assigned.

PerturbRx: Learning Treatment-Conditioned Latent Transitions for Patient Drug Response Prediction

PerturbRx is a treatment-conditioned representation learning framework designed to predict patient-level cancer drug responses despite scarce data and tumor heterogeneity. Existing methods predict response directly from pretreatment molecular profiles and drug representations without explicitly modeling molecular changes expected under treatment. PerturbRx addresses this gap by learning intervention-induced latent transitions from context-matched but cell-unpaired control and treated single-cell populations, using a drug- and dose-conditioned transition predictor. After training, the predictor is frozen and transferred to pretreatment patient profiles, eliminating the need for post-treatment measurements. The learned latent transitions are combined with patient and drug representations to predict response. Across TCGA and patient-derived xenograft benchmarks, PerturbRx achieves the strongest aggregate predictive performance among the evaluated methods, supporting perturbation-pretrained latent transitions as effective representations for patient-level drug-response prediction.

Truthful Calibration Measures for Sequential Prediction

Calibration requires probabilistic reports to be conditionally unbiased and reliably interpretable as probabilities, and a calibration measure assigns numerical error to miscalibrated reports. Building on Haghtalab et al. (2024), who proposed an approximately truthful calibration measure for online prediction, this paper resolves an open question about whether exact truthfulness is compatible with completeness and soundness. The authors prove that for sequential binary prediction, exact truthfulness is incompatible with completeness and soundness, even when outcomes are independent. They then show this impossibility is specific to exact truthfulness by providing two general reductions from a base calibration measure, producing additively and multiplicatively approximately truthful calibration measures. Using the multiplicative reduction, they construct a sound and complete calibration measure that is (1+exp(-T^{(1−ε)/2}/2))-multiplicatively truthful for every 0<ε<1, improving the approximate-truthfulness guarantee of Haghtalab et al. (2024).

Show HN: Kern – container and resource runtime in a 1.5 MB binary, no daemon

Kern is a rootless container and resource runtime delivered as a single 1.52 MB static binary with no daemon, using only libc as its Rust dependency. It launches real OCI images in about 3.5 ms by applying user, PID, mount, network, UTS, and IPC namespaces along with an overlay or read-only root, a deny-by-default seccomp allowlist, and cgroup v2 limits. Beyond isolation, it defines resource profiles for CPU, memory, disk, and devices in a kern.toml file that can be attached to sandboxed boxes or bare host processes alike. Kern accepts existing Docker Compose files unchanged and ships Python and Node SDKs plus an MCP server aimed at running untrusted or AI-generated code. It runs on Linux, WSL2, and ARM boards, with its isolation built on an unprivileged user namespace rather than a hypervisor.

A Claude Code skill that recovers export-blocked Kindle highlights

A Claude Code skill called kindle-highlights recovers Kindle highlights that Amazon's notebook page truncates mid-sentence or hides entirely under an undocumented export limit notice. Running only on macOS, the skill drives a logged-in Chrome session to scrape the notebook's DOM into JSON, then reads exact character positions from the Mac Kindle app's SQLite annotation database to recover highlights the web export hides completely. For still-blocked text, it captures the Cloud Reader's rendered pages via canvas and runs them through a local Apple Vision OCR helper compiled with swiftc, cutting the recognized text to the known highlight extents. The output is a single Markdown file with location-cited, blockquoted verbatim text and flags for recovered or approximate passages. Proven on four books, the pipeline recovered all 815 export-blocked entries out of 2,432 highlights, with recovered text matching the Kindle app's position ruler to within a couple of characters. The skill is scoped to a user's own Amazon account and personal notes.

How Europe is killing makers and micro-entrepreneurs

Lectronz, a marketplace for open-source hardware makers and DIY electronics, warns that the EU's new Packaging and Packaging Waste Regulation (PPWR), generally applying from 12 August 2026, threatens micro-entrepreneurs through its fragmented national compliance requirements. Businesses selling across multiple Member States must register and fulfil obligations separately in each country where their packaging becomes waste, with administrative costs that can reach roughly €1,150 annually even for a small seller operating in just four countries. This creates disproportionate barriers for makers, artists, and craftspeople, given that half of Lectronz's registered sellers receive fewer than 10 orders per year. The author proposes three solutions: an EU-wide de minimis threshold for small sellers, a centralized EPR One Stop Shop similar to the VAT OSS, and allowing marketplaces to collectively represent their sellers as a single producer. The European Commission has proposed suspending the authorized representative requirement until 2035, but this proposal has not yet been adopted.
