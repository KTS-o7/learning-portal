New microblog with TILs

On November 9, 2024, Julia announced a new TIL ("today I learned") section on her site, created a couple weeks earlier to archive interesting tools and facts she had been sharing on Mastodon and Bluesky. The section addresses her need for a place to post brief recommendations—like SQLite's litecli, Go's easy cross-compiling, cryptographic best practices, and the diff tool diffdiff—without writing full blog posts. She built a /til/ folder with tweet-like styling, a `rake new_til` task for quick post creation, and a separate RSS feed, often completing posts in about two minutes. The project was inspired by Simon Willison's TIL blog. While she appreciates the POSSE approach, she prefers keeping most social media content ephemeral and reserves her own site for blog posts, comics at wizardzines.com, and now TILs at jvns.ca/til/, each with email lists and RSS feeds.

Importing a frontend Javascript library without a build system

Frontend libraries can often be loaded directly into a browser via script tags or ES module imports, bypassing npm and bundlers entirely. This approach matters for legacy codebases, CMS integrations, quick prototypes, and environments where installing dependencies isn't feasible, but it also forces you to manage versioning manually, handle global namespace pollution, and forgo optimizations like tree-shaking and automatic TypeScript type resolution that a build system would normally provide.

Why pipes sometimes get "stuck": buffering

When commands are piped together, programs often buffer their output—saving up around 8KB of data before writing—to reduce system calls and improve performance. This causes pipes to appear "stuck" because programs like grep use block buffering when writing to pipes but line buffering when writing directly to a terminal, so output only appears once the buffer fills or the program exits. Commands such as tail, cat, and tee don't buffer, but grep, sed, awk, tcpdump, jq, and tr do buffer by default when writing to pipes. Most of these offer flags to disable buffering, including --line-buffered for grep, -u for sed, -l for tcpdump, and -u for jq. Pressing Ctrl-C kills processes before buffers flush, losing buffered output, though sending SIGTERM to the producing program lets it flush its buffer. Common workarounds include using line-buffer flags, replacing multiple greps with a single awk command, or running programs that finish quickly to avoid the buffering issue altogether.

Decoding Atomicity - The A in ACID

Atomicity, the "A" in ACID, requires that every database transaction be treated as a single unit of execution, meaning either all statements are applied or none are, even after power failures, errors, or crashes. A money transfer between accounts illustrates this: if subtracting from one account and adding to another are only partially applied, money could be lost or never credited. Most databases implement atomicity through logging changes along with transaction start and finish markers, applying or dropping them based on the final state, or alternatively by keeping pre-transaction copies for rollbacks. At the file system level, atomicity is achieved by opening and locking files using system calls like open and flock in shared or exclusive mode. At the hardware level, atomic instructions such as test-and-set, fetch-and-add, and compare-and-swap provide atomic operations. This concept extends beyond databases and can be applied to any system or even to high-level business logic by borrowing atomic instruction constructs.

Decoding Consistency - The C in ACID

Consistency in ACID refers to the correctness of data, ensuring it never loses its integrity under any circumstance. Database systems allow rules to be enforced through constraints, cascades, and triggers such as Foreign Key constraints, Check constraints, and On Delete or On Update Cascades. An ACID-compliant database engine guarantees that data continues to follow all configured rules, moving from one consistent state to another even during thousands of concurrent transactions. When a transaction violates a rule, the engine rolls back the changes to restore a previous consistent state, while successful transactions establish a newer consistent state. A practical example is preventing an account from having a negative balance. Integrity constraints are validated as changes are applied, and cascade operations execute synchronously with the transaction, though some engines offer asynchronous options for leaner transactions.

DeepRepoQA: Code Repository Question Answering with Deep Agent Exploration

DeepRepoQA is a novel question answering framework designed to address repository-level code understanding, a critical yet under-explored problem in software engineering. Existing methods rely primarily on surface-level code retrieval and struggle with deep reasoning across multiple files, complex software architectures, and long-range code dependencies. To overcome these limitations, DeepRepoQA employs an agentic framework in which LLM agents find answers through a systematic tree search over the repository structure. A Monte-Carlo Tree Search (MCTS) mechanism enables agents to dynamically search, navigate, and inspect code, supporting effective multi-hop reasoning over long-range dependencies. Comprehensive experiments on the SWE-QA benchmark show substantial performance gains over strong baselines, validating the effectiveness of systematic MCTS-guided exploration for multi-hop repository reasoning. The framework was developed by Weihan Peng, Yuling Shi, Yingwei Ma, Longfei Yun, Beijun Shen, and Xiaodong Gu.

IncSFS: Incremental Full-Sparse Flow-Sensitive Pointer Analysis for C/C++

Pointer analysis is a fundamental technique for compiler optimization and program analysis, but flow-sensitive pointer analysis offers high precision while being difficult to scale to large projects. To address rapid iteration scenarios where software evolves continuously, the authors introduce IncSFS, the first incremental full-sparse flow-sensitive pointer analysis algorithm for C/C++ programs. IncSFS transforms the value-flow graph into a constraint graph and performs strongly connected component detection to ensure precision, then propagates increases and decreases in points-to sets in an interleaved manner, supporting both code deletion and insertion within a single analysis pass. The algorithm is guaranteed to terminate and compute the least fixed point when the points-to relation remains object-acyclic. Experiments on six large-scale real-world projects demonstrate that IncSFS achieves average speedups of 9.60x over full flow-sensitive pointer analysis, 5.84x over the traditional reset-recompute approach, and 15.8% improvement over state-of-the-art incremental pointer analysis algorithms that propagate points-to-set changes.

NoC-Out: A Formally-verified Network-on-Chip Library for Rule-based Hardware Designs

Network-on-Chip (NoC) systems serve as the communication backbone of multiprocessor chips, making their correctness critical, yet no prior approach offered formally-verified NoCs with strong guarantees without tedious manual effort. The authors introduce NoC-Out, the first library and generator for formally-verified k-dimensional NoC designs. The tool builds on Kôika, a rule-based hardware description language embedded in the Rocq theorem prover, which the authors extended with support for concurrent yet efficient hardware designs and a program logic enabling modular, automated reasoning. Given a configuration, NoC-Out produces a k-dimensional torus NoC in Kôika that can be compiled to Verilog. Each generated NoC comes equipped with a proof that it refines the authors' formal specification, with no additional verification required. The specification establishes a strong liveness guarantee that applies to all generated designs. The authors' evaluation further indicates that this verification approach is necessary for synthesizing efficient NoCs in rule-based hardware description languages.

MGQL: An Executable, Small-Step Semantics of GQL

MGQL is the first mechanized, small-step operational semantics for a substantial read-only fragment of the ISO Graph Query Language (GQL), standardized as ISO/IEC 39075 in 2024. While GQL's semantics is codified informally across over 600 pages of prose, prior formalizations either reduce semantic complexity by omitting features such as bag semantics, schemas, and composite queries, or reduce syntactic complexity by covering only isolated fragments like pattern-matching. Grounded in the ISO/IEC 39075 standard, MGQL models multi-graph property graphs with mixed edge directionality and supports a large fraction of GQL pattern constructs, including quantified paths and edges, directional and undirected matching, label expressions, pattern lists, and composite queries. A schema-aware type system refines variable types via closed-graph schemas, tracks nullability, supports multiple composite query operators, and models quantified-path bindings with list types. The authors prove the type system sound, ensuring well-formed queries yield results conforming to their declared schemas, and the paper was accepted at OOPSLA 2026.

A Literate Programming Environment for Human and Machine Agents

A literate programming environment for human and machine agents is introduced, designed to support the construction of literate programs alongside language-aware machine agents. The environment comprises a grammar for executable program essays, a parser that treats names as first-class objects, and an internal name-graph that links prose, names, and executable artifacts. It also includes a binding mechanism for existing languages and testing toolsets. This design enables co-location of code with its most relevant natural language and structured data context, making better use of Large Language Model context windows. Additionally, it provides LLM coding agents with a toolset analogous to the symbol-aware search and usage information available in human programmer-facing Integrated Development Environments. A working implementation has been developed with bindings to three established programming languages and several example programs.
