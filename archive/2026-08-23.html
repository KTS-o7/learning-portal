Type Construction and Cycle Detection

During Go's type checking process, the type checker constructs internal representations for each type encountered while traversing the abstract syntax tree, a process called type construction. Each type has a completeness property, meaning all its fields are populated and any types it references are also complete, which is required before the type can be safely deconstructed. Recursive types complicate this because evaluating a type expression may return an incomplete type, though type construction itself can proceed since it merely refers to types rather than deconstructing them. However, certain operations like calculating an array's size require deconstruction, which can create impossible-to-satisfy dependencies when types need each other to complete. This results in cycle errors, such as when a type's size depends on itself. Cycle detection handles these cases by operating only on incomplete values in ways that don't deconstruct their types, deferring problematic checks until type checking completes.

//go:fix inline and the source-level inliner

Go 1.26 introduces a new `go fix` implementation featuring a source-level inliner that replaces function calls with copies of the callee's body, enabling automated API migrations through the `//go:fix inline` directive. When placed on deprecated functions like `ioutil.ReadFile`, the directive instructs the tool to inline calls and substitute the new implementation, such as rewriting calls as `os.ReadFile`. The approach extends beyond functions to types and constants, and can correct API design flaws including incorrect parameter ordering or redundant operations. To handle complex scenarios, the roughly 7,000-line inliner manages parameter elimination by emitting "parameter binding" declarations when arguments cannot be safely substituted, and addresses side-effect ordering issues. Despite its technical complexity, the tool has already been used to prepare more than 18,000 changelists in Google's monorepo.

Enabling the next iteration of the borrow checker on nightly

The next iteration of the Rust borrow checker, called Polonius Alpha, is being enabled on nightly in preparation for stabilization later this year. Its key advantage over NLL is flow-sensitive borrow checking of lifetime outlives relationships, allowing code that NLL incorrectly rejects to compile, such as certain `match` arms where a borrow isn't live in every branch. Polonius Alpha is not a strict superset of the original Polonius, as some programs that previously compiled under legacy Polonius don't compile under Alpha. Performance testing on the top 10,000 crates by downloads shows relatively few significant regressions, with the worst cases outside this set showing a 2-3x slowdown. Developers can opt out of Polonius Alpha on nightly using `-Zpolonius=off`. The team plans to monitor reported issues, address performance regressions, and stabilize the feature before the end of the year, though no concrete plans exist for further Polonius feature work beyond Alpha.

crates.io: development update

Over the past six months, crates.io added a "Code" tab to crate pages that lets users browse published files directly on the site, supported by a file tree sidebar with search, syntax highlighting, and shareable line-selection URLs. A version-to-version diff viewer built on the same infrastructure is in development. The team accepted RFC #3946, introducing crates.io-native usernames independent of GitHub, with implementation underway. Crates flagged as unmaintained by RustSec now display a warning banner, while superseded crates show a "You might not need this dependency" banner with a light bulb icon in dependency lists. The frontend was successfully ported from Ember.js to Svelte, reaching feature parity and becoming the default in May. Several under-the-hood improvements were also made, including faster search ranking, a rewritten ARCHITECTURE.md document, better CDN caching, and accessibility enhancements verified by ARIA snapshot tests.

Inducing Task Models from Computer-Use Traces

The paper "Inducing Task Models from Computer-Use Traces" by Yucheng Jiang, Zora Zhiruo Wang, Ruishi Chen, and Diyi Yang introduces Task Model Induction (TMI), a method for deriving symbolic, reusable task models from passively recorded computer-use traces such as screenshots and mouse or keyboard actions. TMI addresses the challenge of modeling real-world work by discovering the latent tasks within unconstrained traces and disentangling concurrent, interleaved activities. For each latent task, it produces a structured task model that pairs a hierarchical objective model of recursive goal decomposition with a procedure model of control flow. In intrinsic evaluations on controlled human and agent trajectories, TMI recovers interleaved tasks with 0.974 agreement against ground-truth groupings and reconstructs 74.9% of observed execution steps, far surpassing the strongest workflow induction baseline. Extrinsically, skills derived from these task models improve held-out task accuracy by 30.0% over the strongest baseline.

Pandora's AI Model Routing Box: Efficient Allocation with Costly Value Estimation

Heterogeneous AI systems can improve quality and efficiency by routing queries to specialists best suited to answer them, but routing requires estimating each specialist's expected return. This estimation carries a cost, as cheap predictors like embedding-based models are fast yet noisy, while accurate fine-tuned estimators are expensive. The authors formalize this tradeoff as an instance of Pandora's Box, the classical optimal search problem with costly inspection. Under a Gaussian signal model, their approach yields closed-form value-of-information expressions that determine when refining an estimate is worth its cost, producing a centralized policy called Pandora's Router. They also introduce a decentralized variant, Pandora's Bidder, where specialists independently decide whether to invest in self-assessment before accepting a price. Experiments across three domains—a multi-LLM benchmark, retrieval-augmented specialists, and LLMs with variable inference-time reasoning—show that Pandora's Router matches exhaustive estimation quality while querying the expensive estimator far less often. In the decentralized setting, value-of-information reasoning improves allocative efficiency when competing estimates are accurate, but when estimates are noisy, it can increase the strategic specialist's utility at the expense of others.
arXiv (Adam Fisch et al.)

Explainable Transformer Models for Clinical Prediction Tasks on Structured Electronic Health Records

The authors present BERT-LER, a BERT-style transformer model designed for predictive tasks on structured electronic health records (EHRs). The model is pretrained and fine-tuned on a de-identified dataset of 75 million patients and encodes laboratory test results as discrete tokens while preserving graded information through percentile-based binning. To address interpretability, the authors pair the architecture with Integrated Gradients for token-level attributions grounded in input EHR sequences. The approach is benchmarked on the public EHRShot suite and on a real-world asthma severity progression study. Across these tasks, BERT-LER achieves predictive performance competitive with publicly available benchmark models and often exceeds them on laboratory-related tasks, while its attributions align with clinically known risk factors. The framework unifies laboratory value representation and explainability within a single modeling approach applicable across therapeutic areas using language models trained on structured EHRs.
arXiv (Jun Ni Du et al.)

MidTool: Mid-training Data Synthesis for Agentic Tool Use

The paper presents MidTool as an open corpus-construction pipeline for agentic tool use, combining large-scale web, PDF, and code data with synthesized supervision based on real-world tool APIs, MCP skills, and document-grounded workflows. Its training objectives are to help models recognize tool affordances, ground arguments in context, compose tool-call workflows, and recover when information is incomplete. The authors mid-train Qwen3-4B-Base and Qwen3-8B-Base on MidTool-Mix, then apply supervised fine-tuning and reinforcement learning. Across BFCL, tau2-Bench, and MCP Universe, MidTool-Mix consistently improves downstream performance over baselines under both post-training approaches. The results suggest that general tool use benefits from dedicated mid-training rather than being left entirely to post-training.
arXiv (Fengqing Jiang et al.)

Canada will match US tariffs 'dollar for dollar' as trade talks break down

Canada announced it will impose reciprocal tariffs "dollar for dollar" on US goods after trade negotiations broke down just before a Friday deadline. Prime Minister Mark Carney suspended talks, citing last-minute changes in US proposed terms as "unfair, uneconomic" and questioning the reliability of any deal. New 50% US tariffs, imposed under the Tariff Act of 1930, took effect Saturday on about 5% of Canadian exports including wine, dairy, cement, clothing, and hockey equipment, in addition to existing tariffs on steel, aluminum, autos, and lumber. US Trade Representative Jamieson Greer countered that Canada declined to finalize the deal under previously agreed terms. The breakdown follows months of on-again, off-again negotiations, with economists estimating Canada could lose 90,000 jobs and see its GDP reduced by 0.3% to 0.6%.

Stop Making TUIs

The author argues that terminal user interfaces (TUIs) are outdated products of 1970s teletype constraints and should largely be abandoned, though command-line interfaces remain valuable. Using LLMs, he has built numerous native SwiftUI applications for personal use—including a Markdown viewer, a SageMath calculator frontend, an Apple Music player with an embedded agent, a self-driving wiki, a food tracker, and an Apple TV remote—without hand-writing the UI code. He contends that even strong TUI frameworks like Ratatui, Textual, or Bubbletea require fighting the terminal to approximate standard features such as scrolling, drag-and-drop, text selection, and image handling, all of which work out of the box in native toolkits. While acknowledging TUIs offer speed and information density, he maintains they exist primarily due to historical inertia rather than inherent advantages. The shift to LLM-assisted native UI development, he suggests, has made graphical customization as accessible as command-line work once was.

Rust Glancer: Rust LSP using 100x less RAM

Rust Glancer is a Rust language server that targets under 100MB of memory usage, significantly less than rust-analyzer. It performs a one-time full indexing of the workspace and persists results to the filesystem, allowing immediate reuse after editor restart without re-indexing. The approach differs from rust-analyzer's incremental salsa-based database by using frozen analysis results that are invalidated only on save, though this makes it slower since data must be loaded from disk rather than memory. The project has implemented a full indexing pipeline with type inference, Chalk-based trait solving, declarative macro expansion, and supports goto definition, hover, inlay hints, and completions. Built over four months, it achieves indexing speeds comparable to rust-analyzer but comes with trade-offs, including delayed indexing of newly added items until the file is saved.

Scrap (2006)

Moxie Marlinspike shared an old journal entry from circa 2006 about moving from the west coast to Pittsburgh, where he arrived unprepared for the harsh winter and found his new house lacking working utilities and heating. After learning that Pittsburgh scrappers hunt for raw metals rather than thrift-store finds, he began leaving unwanted items like a rusted cast-iron bathtub in his yard to be collected. Two scrappers named Ron and Wade arrived in a pickup truck and agreed to haul a heavy broken gas furnace out of his basement for scrap. The 17-step extraction proved chaotic: Wade, missing three toes due to "the sugars," panicked from claustrophobia in the narrow stairwell and tried scrambling over the furnace while Moxie pushed him through a two-foot gap. Ron solved a stuck pipe by chopping it with an axe, and the men hauled the furnace out the front door, noting that steel scrap earns four cents a pound.
