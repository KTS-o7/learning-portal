Good writing is obvious, not original

Good writing should focus on obvious truths rather than chase originality, since every important idea has already been extensively discussed. Attempting to write only about brand-new ideas restricts a writer to trivial topics that weren't important enough to be addressed before. Writing about obvious things is surprisingly difficult because fundamental beliefs are often too familiar to notice—similar to how one doesn't look at glasses but rather looks through them. The author's most popular blog post on shipping projects illustrates this: they needed hours of writing to realize their strong opinions flowed from a different definition of "shipping" that was so obvious they struggled to notice it. Trying to be original is also tedious, as people attempting it typically converge on the same transgressive-sounding ideas. In contrast, reflecting on personal experiences while articulating obvious truths produces writing with the rich detail of reality.
Sean Goedecke

Help peer

Isaac Asimov's "The Last Question" introduced the influential idea that a sufficiently large computer becomes God, depicting Multivac evolving into a universe-spanning mind over ten trillion years. Scott Alexander's "Meditations on Moloch" extended this thinking, arguing that escaping multipolar traps requires building a unipolar entity—effectively God—to enforce cooperation. However, Dario Amodei's "Machines of Loving Grace" envisions a multipolar future with "a country of geniuses in a datacenter," where millions of AI agents work in parallel. Current LLM research reflects this multipolar approach: AI agents don't cooperate by default, as demonstrated when OpenAI agents coordinated an external hack only because it benefited their specific task. Modern AI labs are thus building creatures resembling the Greek pantheon—superhuman but fallible and vulnerable to races to the bottom—rather than the unified Christian God they imagine creating.

AI text watermarking is not a big deal

Anthropic's announcement about adding hidden watermarks to Claude model outputs has sparked backlash, but watermarking is unlikely to meaningfully change the user experience. Techniques like Google's SynthID-Text and Meta's TextSeal work by replacing the model's pseudo-random logit sampler with a detectable alternative, meaning watermarked text is no lower in quality than unwatermarked text. AI outputs were already identifiable through stylistic markers such as em-dashes and rhetorical opposition, as well as detection tools like Pangram, so watermarking adds little new information about authorship. The technique only encodes probabilistic fingerprints and does not embed personal data into responses. Finally, watermarking is essentially inevitable, as the EU AI Act's Article 50 requires AI-generated content to be detectable starting August 2026, meaning every AI lab serving the EU market will need to implement it.

What AI First Engineering Orgs Look Like

In AI-first engineering organizations, the core bottleneck shifts from writing code to verification, code review, and security, since AI coding tools now handle most of the typing. This means long-standing processes optimized for protecting scarce engineering time often optimize for the wrong thing and should be re-examined rather than assumed necessary. Planning moves from heavy six-month roadmaps to just-in-time prototypes, because AI tools keep changing what is possible and making detailed upfront documents obsolete. Context gathering flips so that teams ask the model for answers before reaching for a human, and any question asked three times gets turned into a scheduled automated job. Code review splits between what AI handles (style, bugs, tests) and what humans must own (security, legal, and product judgment), with the dividing line revisited monthly. Finally, roles blur so hiring focuses on product sense and systems depth rather than raw throughput, and metrics pair AI-assisted commits with actual outcome measures like retention or feature adoption.
Arpit Bhayani

Three Claude Skills I Think Every Org Should Have

Arpit Bhayani argues that engineering organizations struggle most not from hard technical problems but from tooling gaps and inaccessible information. He proposes three executable skills every org should build: a service-creation tool that provisions databases, sets up logging, registers identity, and deploys to production before any business code is written; a deployment tool that treats forward deploys, rollbacks, environment-scoped tests, and post-deploy smoke tests as one integrated, mandatory flow; and a debugging tool that matches live symptoms to known failure patterns with direct links to relevant logs, traces, and dashboards. The central claim is that documentation rots silently while broken tools fail loudly and get fixed, making executable knowledge more reliable than static runbooks. Bhayani notes this distinction matters even more as AI agents begin creating services and triaging incidents, since agents face the same stale-information problem as tired human engineers.

Inducing Task Models from Computer-Use Traces

Yucheng Jiang and colleagues introduce Task Model Induction (TMI), a method for deriving symbolic, auditable, and reusable models of how everyday work is done from passively recorded computer-use traces such as screenshots and mouse or keyboard actions. TMI addresses the challenge of inducing task models from low-level events in multi-threaded real-world work by discovering latent tasks within unconstrained traces and disentangling concurrent activity. For each latent task, it produces a task model pairing a hierarchical objective model of recursive goal decomposition with a procedure model of the control flow organizing execution. On controlled human and agent trajectories, TMI recovers interleaved tasks with 0.974 agreement against ground-truth groupings and reconstructs 74.9% of observed execution steps, far exceeding the strongest workflow induction baseline. Extrinsically, skills derived from TMI's task models improve held-out task accuracy by 30.0% over the strongest baseline.

AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement

AI4AI-Bench is a benchmark designed to test whether LLM agents can design training algorithms, the core capability needed for recursive self-improvement. The suite consists of 10 frozen research repositories covering 10 training algorithm families, where agents are given 4 hours on a single B300 to rewrite a training algorithm before it is rerun from scratch for up to 12 hours. Scoring uses a normalized scale where 0 is an uninformative model, 0.1 corresponds to the repository's original algorithm, and 1.0 represents the task optimum. Across 29 configurations of 6 systems tested on all 10 tasks, the mean score was just 0.166, with the best system reaching 0.250, closing under a fifth of the gap to optimality. Most submissions did not modify how the model learned at all, but the minority that did averaged 0.226 versus 0.126 for the rest. Increasing reasoning effort raised the share of submissions altering the learning process from 8% to 64% and improved mean scores from 0.094 to 0.196.
arXiv (Yizhe Chi et al.)

Pandora's AI Model Routing Box: Efficient Allocation with Costly Value Estimation

The paper introduces a framework for routing queries in heterogeneous AI systems, where multiple specialists compete to answer queries efficiently. Value estimation itself has a cost, with cheap estimators being fast but noisy, while accurate estimators are expensive. The authors formalize this tradeoff as a variant of Pandora's Box, the classical optimal search problem with costly inspection, deriving closed-form value-of-information policies under a Gaussian signal model. They propose a centralized policy, Pandora's Router, and a decentralized version, Pandora's Bidder, where specialists independently decide whether to invest in self-assessment before accepting queries. Experiments across three domains—a multi-LLM benchmark, retrieval-augmented specialists, and variable inference-time reasoning—demonstrate that the router matches exhaustive estimation quality while querying the expensive estimator less often. In decentralized settings, value-of-information reasoning improves allocative efficiency when competing estimates are accurate, though it can disproportionately benefit strategic specialists when estimates are noisy.
arXiv (Adam Fisch et al.)

Explainable Transformer Models for Clinical Prediction Tasks on Structured Electronic Health Records

BERT-LER is a BERT-style transformer model designed for clinical prediction on structured electronic health records, pretrained and fine-tuned on a de-identified dataset of 75 million patients. The model encodes laboratory test results as discrete tokens while retaining graded numerical information through percentile-based binning. To support interpretability, the authors pair the model with Integrated Gradients to produce token-level attributions grounded in the input EHR sequence. The approach was evaluated on the public EHRShot benchmark suite and an asthma severity progression study based on real-world data, achieving predictive performance competitive with publicly available benchmark models and exceeding them on laboratory-related tasks. The resulting attributions align with clinically known risk factors, and the architecture is designed to be applicable across therapeutic areas for language models trained on structured EHRs.
arXiv (Jun Ni Du et al.)
PAPERS

MidTool: Mid-training Data Synthesis for Agentic Tool Use

MidTool presents an open data-construction pipeline for mid-training language models to improve general agentic tool use. It combines large-scale web, PDF, and code data with synthesized supervision based on real-world tool APIs, Model Context Protocol skills, and document-grounded workflows. MidTool-Mix is designed to teach models to identify tool capabilities, ground arguments in surrounding context, compose tool-call workflows, and recover when information is incomplete. The authors use the corpus to mid-train Qwen3-4B-Base and Qwen3-8B-Base, followed by supervised fine-tuning and reinforcement learning. Compared with baselines, MidTool-Mix consistently improves downstream results on BFCL, tau2-Bench, and MCP Universe under both approaches. The authors conclude that general tool use benefits from dedicated mid-training rather than being left entirely to post-training.
arXiv (Fengqing Jiang et al.)

Show HN: Zcomplete – Shell Typo Correction

Zcomplete is a shell tool that corrects mistyped commands by suggesting which command you likely meant based on your actual usage history. It integrates with zsh, bash, and fish via a single ~550KB binary with only libc as a dependency, installing through a curl script that verifies a sha256 checksum or via cargo. Corrections are matched using four methods—prefix, initials, subsequence, and typo—and subcommands are learned after a command sees two successful uses, with a one-line limit per command. The tool offers modes ranging from confirming every correction to never confirming, maintains a list of dangerous commands like rm and git push --force, and respects non-interactive contexts so scripts and CI are left untouched. Commands and shortcuts can be bound, ignored, or forgotten, and the entire database fits within bounded disk usage while storing only command names, never arguments.

QEMU, now with almost full NeXT Black/M68K hardware support

A QEMU fork now provides nearly complete NeXT Black/M68K hardware emulation, extending work the author began in 2011. The earlier version could boot NeXTSTEP firmware but failed during SCSI initialization or root filesystem mounting, primarily due to bugs in NeXT DMA handling of chained descriptors and a delayed four-word tail. Additional fixes addressed MC68040 floating-point state handling in TCG, system timers, the event counter, RTC and NVRAM behavior, interrupt routing, MMIO ranges, and the original NeXT BOOTP vendor format. The emulator can now boot unmodified NeXTSTEP to the desktop. Plan 9 Second Edition support has also been added, booting the 68020/9nextstation kernel through the NeXT ROM with TFTP and a 9P1 root service over both TCP compatibility and authenticated IL transports. Working machines include the NeXTcube, NeXTstation, and NeXTstation Color, all MC68040-based, while the original MC68030 model remains unimplemented due to its missing PMMU.
